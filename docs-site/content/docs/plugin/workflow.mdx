以同一项目目录为例，依次走完上面的步骤。创建目录必须不存在；文件写好之后才安装依赖。编辑 pages 时保留唯一 label，并为图、数据和公式写清来源。

## 检查通过意味着什么

deck.check 验证可自动检查的资源、画布、溢出和打印布局，同时生成逐页截图。检查成功后仍要逐页核对内容、公式与视觉效果；报告不能代替内容审阅。

更改源码后重新 build 再 check。export 读取构建产物并再次检查，不会替你把源码编译成最新网页。

## 两种交付

网页交付整个 dist，通过 HTTP 静态服务放映。PDF 使用新文件名，已有同名 PDF 会被拒绝覆盖。当前不生成可编辑 PPTX。

## 失败时从哪里查

| 现象 | 下一步 |
| --- | --- |
| create 目录已存在 | 选新目录，或继续编辑已有项目 |
| build 缺 Vite 或组件 | 在汇报目录完成 pnpm install |
| check 无 dist | 先 deck.build |
| 无浏览器 | 安装 Chrome，或选择已安装的 Edge |
| 检查失败 | 读 .artifacts/check.json 和截图，修正文后重新构建 |
| 导出文件已存在 | 使用新的 out 绝对路径 |

命令的真实入参、返回与超时见 [命令契约](/docs/plugin/commands)。
